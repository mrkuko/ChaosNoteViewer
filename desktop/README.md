# Desktop client (Linux + Windows)

Qt 6 / QML + C++ 17 tray app. Built with CMake.

## Build and run

Linux:

```
cmake -S . -B build
cmake --build build
./build/chaosnoteviewer
```

Requires Qt 6.5+ (Quick, QuickControls2) and Python 3 for `generate.py`, which CMake runs.

Windows (installs Python, CMake, Ninja, MSVC Build Tools via winget and Qt via aqtinstall, then builds
into `dist\`; re-runnable):

```
powershell -ExecutionPolicy Bypass -File .\build-windows.ps1
```

## Plasma widget

```
./install.sh
```

Installs or upgrades `plasmoid/`. It first copies the shared SQL migrations from
`../core/storage/migrations/` into `plasmoid/contents/ui/Migrations.js` (generated, not committed),
because the widget cannot read `core/` at runtime. Run it again after every change in
`core/storage/migrations/`. If the widget does not refresh: `plasmashell --replace &`.

### Sign-in (Firebase)

The app works without an account. To sign in and sync, give it your own Firebase project: the **Web API key** and the
**Project ID** (Firebase console, Project settings, General). The project needs Email/Password sign-in enabled and a
Firestore database with the rules from `../core/firebase/firestore.rules`. On first open the app asks for both
(Settings, Firebase project, with an Edit button afterwards); they are kept in the local database. The Project ID field
starts as `chaosnoteviewer`, the author's own project: replace it with yours. Changing the project signs you out and the
notes of this device go up to the new project again.

**Adding another device:** Settings, Show key shows a QR code with the whole setup: the Firebase project (Web API key,
Project ID) and the encryption key, in the form `chaosnote:setup?v=1&p=<project id>&a=<api key>&k=<key>`. The phone app
scans it; on another computer, Copy setup code and paste it into the Web API key field. The sign-in is never part of it:
the new device still signs in with your email and password.

Alternatively, a key can be built in as the default, and it is not committed:

```
cp firebase.local.example.json firebase.local.json     # then paste the apiKey (and your projectId) into it
./install.sh
```

`install.sh` writes it, with the project id (`projectId` in that file, otherwise the one in
`../core/firebase/.firebaserc`), into `plasmoid/contents/ui/FirebaseConfig.js` (generated, not committed). Set
`"emulator": true` in `firebase.local.json` to use the local Auth emulator (`npm run emulators` in `core/firebase`) instead.

The first account that signs in owns the notes on that device. Signing out keeps the notes,
and only that account can sign in on the device again. The refresh token that keeps you signed in
is stored in the local database without encryption.

### Sync and encryption

Once signed in (and the email is verified) the widget syncs with Firestore: changes are pushed a
couple of seconds after they happen, remote changes are pulled every 30 s while the widget is open
and every 5 min otherwise (slower while offline). Notes are encrypted on the device with
ChaCha20-Poly1305 (`Crypto.js`) before they are uploaded.

- **Key:** the first device creates a random key and shows it. Save it: it is needed to add another
  device and cannot be recovered. Settings, Account shows or copies it again at any time, also as a QR
  code (just the key text) for a phone's camera. It is stored in the local database, next to the notes it
  protects the cloud copy of.
- **Lost the key:** Settings, Reset key deletes everything in the cloud, creates a new key and uploads
  this device's notes again. Other devices are asked for the new key.
- **Deleting** removes the note from the cloud for real, the local copy goes once the server confirmed.
  A device that still has a note deleted elsewhere shows it with a red dot: upload it again or delete it.

### Code layout: one app, two launchers

All app logic is written once, in `shared/`: `AppController.qml` (notes, account, encryption key, sync, as
one non-visual QML item), `NoteStore.js`, `Auth.js`, `Sync.js`, `KeyFlow.js`, `Crypto.js`, `QrCode.js` with `QrImage.qml`. Two launchers
use it:

| | Plasma widget (`plasmoid/`) | Tray app (`src/`, `qml/`, CMake) |
|---|---|---|
| gets the shared files by | `install.sh` copies them into the package | CMake lists them in the QML module |
| UI | `plasmoid/contents/ui/main.qml` (Plasma, Kirigami) | `qml/` (Qt Quick Controls, Basic style, dark theme in `Theme.qml`; the same screens as the widget, logic through `TrayController`) |
| secure random bytes | `/dev/urandom` through Plasma's executable engine | `SecureRandom` (C++), the OS generator via `QRandomGenerator::system()`: `BCryptGenRandom` on Windows, `getrandom` on Linux |

`shared/Migrations.js` and `shared/FirebaseConfig.js` are generated by `generate.sh` (run by both
`install.sh` and CMake) and not committed. QML has no secure random numbers, so every launcher gives
`AppController` an `entropy(n, callback)` function; nothing else in the shared code depends on the platform.
